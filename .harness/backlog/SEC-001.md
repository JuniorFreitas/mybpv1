# TASK: SEC-001

## Título
Mitigar CVE-2026-115560 (PHP session upload progress RCE path)

## Tipo
Security Finding

## Objetivo
Eliminar a pré-condição explorável `session.upload_progress.enabled=On` no runtime PHP-FPM do MyBP até existir patch oficial do PHP.

## Contexto
Advisory informativo da PHP Foundation (2026-10-23). Vetor improvável de RCE quando:
1) `session.serialize_handler` está em `php_binary` ou `php_serialize` na config;
2) a aplicação troca para `php` via `ini_set()` antes de `session_start()`;
3) upload progress permanece habilitado.

MyBP local: PHP 8.2.8, `serialize_handler=php`, `upload_progress.enabled=1` (antes da mitigação). Nenhum uso de `ini_set('session.serialize_handler')` no código da aplicação.

## Descrição
- Desabilitar `session.upload_progress.enabled` nos php.ini de deploy.
- Aplicar `php_admin_flag` no pool FPM para impedir override via `ini_set`.
- Validar no container e registrar evidências.

## Critérios de aceitação
- DADO o container `mybpdp` com a config de deploy, QUANDO o PHP-FPM carregar a configuração, ENTÃO `session.upload_progress.enabled` está Off/0 e não é sobrescrevível via `ini_set`.
- DADO o repositório, QUANDO o script `start` rodar, ENTÃO copia o pool conf de mitigação para `/etc/php/8.2/fpm/pool.d/`.
- DADO a aplicação MyBP, QUANDO não houver uso de progress bar via `$_SESSION` nativo do PHP, ENTÃO uploads continuam funcionando.

## Estimativa
Baixa. Premissa: MyBP não depende de `session.upload_progress` do PHP.

## Riscos
- Barras de progresso baseadas em `PHP_SESSION_UPLOAD_PROGRESS` deixam de funcionar (não observado no código MyBP).
- Mitigação não substitui upgrade futuro do PHP quando o patch oficial for publicado.
- Produção/ECS só fica protegida após redeploy da imagem/config — exige aprovação de deploy.

## Validação
- `php -r 'echo ini_get("session.upload_progress.enabled");'` no CLI após copiar ini (referência).
- Verificar FPM via restart + leitura do pool conf e, se possível, `php-fpm -i` / endpoint web.
- Confirmar ausência de `ini_set('session.serialize_handler'` no app.

## Evidências
- Antes (CLI no `mybpdp`): `upload_progress.enabled=1`, `serialize_handler=php`, PHP 8.2.8.
- Depois (HTTP via Nginx→FPM, probe temporário removido):
  - `upload_progress.enabled=''` (Off)
  - `serialize_handler=php`
  - `ini_set('session.upload_progress.enabled','1')` retornou `false` (admin flag efetiva)
  - `after_ini_set` permaneceu Off
- Artefatos: php.ini production/development; pool `zz-cve-2026-115560.conf`; `start` copia o pool conf.

## Resultado
Mitigação aplicada e validada no ambiente Docker local. Produção/ECS permanece pendente de redeploy (aprovação humana). Patch oficial do PHP ainda não publicado para este CVE.
