# TASK: TD-004 — Form Requests + multi-tenancy em toda a aplicação

## Título
Migrar `Validator::make` dos controllers para Form Requests com escopo de tenant

## Tipo
Technical Debt | Security Finding (multi-tenant)

## Objetivo
Eliminar validação inline nos controllers HTTP da aplicação autenticada, usando Form Requests e `ValidatesTenantOwned` (`Rule::exists(...)->where('empresa_id')`) em IDs de entidades multi-tenant.

## Contexto
TD-001 cobriu Admissão/Aprovação Extra/Movimentação. Inventário 2026-11-23: **97 controllers** ainda com `Validator::make`. PO pediu cobertura total com time DevTeam (Backend + Security + QA + Code Review).

## Descrição
Ondas:

| Wave | Escopo | Controllers (amostra) |
|------|--------|------------------------|
| A | RH operacional | PosAdmissao, PreAdmissao, Cih, Intermitente, Parecer*, Entrevista*, Historico, ResultadoIntegrado, PromocaoFeedback, FeriasFeedback, Afastamento* |
| B | Cadastros | CentroCusto, Vaga, VagasAbertas, Departamento, Filial, Projeto, Beneficio, User, Empresa*, AreaEtiquetas, Municipio |
| C | Treinamentos / Exames / Docs | Treinamento*, EmpresaTreinamento, Instrutor, ControleExame, EmpresaExame, Pcmso, DocumentosLegais*, Documento*, Dossie*, CarteiraAssinatura |
| D | Operacional / Avaliação / Cloud | Ocorrencia*, Tarefas*, Quadro*, Cloud*, Avaliacao*, Avaliador*, Nps, PesquisaClima, Checklists* |
| E | Admin / Financeiro / API | FluxoCaixa, PlanoConta, FormaPagamento, Clientes, Fornecedor, Papeis, Habilidades, Api/*, Auth/Register |

Padrão obrigatório: `App\Http\Requests\Concerns\ValidatesTenantOwned`.  
Tabelas globais (sem `empresa_id`): não forçar tenant (ex.: `areas`, `periodos_aquisitivos`, municípios IBGE quando aplicável).

Backend

## Colaboradores

## Status

## Dependências
- Trait `ValidatesTenantOwned` (já entregue)
- SEC-001/002 continuam **adiados** (fora do escopo)

## Critérios de aceitação
- DADO um store/update com ID de outra empresa, QUANDO validar Form Request, ENTÃO falha com 400 e erro no campo
- DADO controller migrado, QUANDO buscar `Validator::make` no método store/update migrado, ENTÃO não existe
- DADO suite unitária Form Requests, QUANDO rodar no Docker SQLite `:memory:`, ENTÃO passa
- DADO tabela sem `empresa_id`, QUANDO validar, ENTÃO não aplica `existsNaEmpresa` indevido

## Estimativa
Grande (multi-onda). Premissa: store/update primeiro; aprovações/ações auxiliares sob demanda se regras forem triviais.

## Riscos
- Regras com closures/estado dinâmico (ex.: custom fields) podem permanecer no controller após Form Request base
- Soft deletes: preferir `whereNull('deleted_at')` quando a tabela tiver soft delete e a regra exigir registro ativo
- Quebra de contrato JSON de erro (manter `msg` + `erros`, status 400)

## Validação
- PHPUnit Form Requests + regressão Feature afetadas (AprovacaoExtra, WhatsApp se tocado)
- Code review + QA verifier ao fechar cada wave
- Security auditor ao fechar Wave A/B (dados pessoais / tenant)

## Resultado
