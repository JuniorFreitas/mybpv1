# BUG: BUG-004 — GET /g/usuario/autenticado retorna 500

## Descrição
Endpoint `UserController::getUsuario` quebra com HTTP 500 ao abrir Configurações (e outras telas que chamam `/usuario/autenticado/`).

## Passos para reprodução
1. Autenticar como usuário com vínculo em `cliente_funcionarios` para um cliente fora de `empresa_clientes` (ClientesEmpresa).
2. Abrir tela que chama `GET /g/usuario/autenticado/` (ex.: aba Configurações).

## Resultado esperado
HTTP 200 com payload do usuário autenticado (`area_id`, `apelido`, etc.).

## Resultado observado
HTTP 500 — `Attempt to read property "area_id" on null` em `UserController.php:226`.

## Severidade
High

## Prioridade
High

## Ambiente
local · userId 50393 · empresa_id 104 · pivot cliente_id 60331

## Evidências
`storage/logs/laravel.log`: ErrorException area_id on null; diagnóstico: Cliente 60331 existe, mas global scope `scopeCliente` filtra por `ClientesEmpresa` (60331 ausente).

## Causa raiz
Confirmada — `$cliente->Cliente` aplica global scope de `Cliente` (`whereIn id ClientesEmpresa`); pivot aponta para cliente fora dessa lista → relação null → acesso a `area_id` sem null-safe.

## Correção
Null-safe no scope de tenant: `$clienteFuncionario?->Cliente?->area_id ?? 0` (sem `withoutGlobalScopes`). Pivot fora de `ClientesEmpresa` → `area_id=0`, sem 500 e sem vazar área cross-tenant. `apelido` via `empresa_id` do auth com scope.

## Teste de regressão
Feature: pivot fora do tenant → 200 + `area_id=0`; cliente no tenant → `area_id` correto; sem pivot → `area_id=0`.

## Status
DONE

## Evidência pós-fix
- `tests/Feature/UsuarioAutenticadoTest.php` — PASS (Docker SQLite `:memory:`).
- Revisão multitenancy: `withoutGlobalScopes` na 1ª versão foi removido por vazar `area_id` de cliente fora do tenant.
