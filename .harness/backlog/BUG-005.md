# BUG: BUG-005 — Solicitação de férias rejeita colaborador_id válido

## Descrição
Ao solicitar férias com colaborador selecionado (UI com check verde), a API retorna 400:
`colaborador_id: O valor selecionado para o campo colaborador_id é inválido.`

## Passos para reprodução
1. Abrir Movimentação → Solicitação de férias.
2. Selecionar colaborador admitido (ex.: ALEXANDRE DE SOUSA FERREIRA).
3. Preencher período, dias, datas e gestor.
4. Salvar.

## Resultado esperado
Solicitação criada (201).

## Resultado observado
Toast "Erro ao Solicitar Férias" com validação de `colaborador_id` inválido.

## Severidade
High

## Prioridade
High

## Ambiente
Local / produção (Form Request introduzido em Nov/2026).

## Evidências
- `Colaborador.vue` (`tipo === 'ferias'`): `colaborador_id = obj.feedback_id`.
- Autocomplete `colaboradoresFerias` retorna `feedback_id` de `feedback_curriculos`.
- `StoreFeriasPrevistaRequest` validava `regraIdNaEmpresa('users')`.
- Controller `buscaDataAdmissao` usa `Admissao::whereFeedbackId($dados['colaborador_id'])`.

## Causa raiz
Confirmada — regressão de segurança multi-tenant: `colaborador_id` em férias é `feedback_curriculos.id`, não `users.id`.

## Correção
Validar `colaborador_id` com `regraIdNaEmpresa('feedback_curriculos')`. Manter `gestor_id` em `users`.

## Teste de regressão
`tests/Unit/Http/Requests/StoreFeriasPrevistaRequestTest.php` — payload com feedback da empresa passa; ID de `users` / outra empresa falha.

## Status
DONE

## Evidência de teste
`docker compose exec -T mybpdp php artisan test --filter=StoreFeriasPrevistaRequestTest`
4 passed (9 assertions).

Browser local: POST ferias-prevista com feedback_id 1698 → HTTP 201.

## Mapeamento outras movimentações (2026-11-26)

Invariante do domínio: `curriculos.id === users.id` (ver `User::Curriculo()`).

| Fluxo | Front envia | Form Request valida | Resultado |
|-------|-------------|---------------------|-----------|
| Férias (store) | `feedback_id` | `feedback_curriculos` (após fix) | OK |
| Demissão store/update | `curriculo_id` | `users` | OK (IDs coincidem) |
| Valor Extra store/update | `curriculo_id` | `users` | OK |
| Muda Cargo Prevista store/update | `curriculo_id` | `users` | OK |
| Intermitente→Fixo store/update | `curriculo_id` | `users` | OK |
| Transferência store/update | `curriculo_id` | `users` | OK |
| Mudança Cargo (`StoreMudancaCargo`) | `curriculo_id` | `users` | OK |
| Admissão prevista | sem `colaborador_id` | n/a | OK |
| Requisição de Vaga | sem `colaborador_id` (só gestor) | `users` no gestor | OK |

Simulação real (empresa 63122): curriculo passa em todos os stores/updates acima; feedback_id falha em todos exceto Férias.

### Residual (alinhado 2026-11-26)
`FeriasPrevistaEditPayloadMapper` passou a devolver `colaborador_id = feedback_id` (mesmo contrato do create / `Colaborador.vue` tipo=ferias). Teste `FeriasPrevistaEditPayloadMapperTest` atualizado.
