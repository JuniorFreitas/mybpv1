# TASK: TD-005 — Soft deletes em Form Requests / validação

Tipo: Technical Debt | Pri: High | Status: DONE | DevTeam: follow-up TD-004

## Problema

Exists/unique em Form Requests aceitavam IDs soft-deleted; unique bloqueava reuso de labels de registros apagados. Cache de `Schema::hasColumn` em trait PHP era por classe (limpar via trait name não limpava Requests).

## Entregue

1. `SoftDeleteSchema` — cache compartilhado + `limpar()` para testes
2. `ValidatesTenantOwned`: `existsNaEmpresa` / `existsAtivo` / `uniqueNaEmpresa` / `aplicarSoftDeleteSeExistir` com `whereNull(deleted_at)` quando a coluna existir
3. `TenantUniqueRules` alinhado ao mesmo helper
4. Closures `Rule::unique()->where` em Form Requests chamam `aplicarSoftDeleteSeExistir`
5. Exists globais → `existsAtivo` / `regraIdAtivo` (município, CBO, período aquisitivo, etc.)
6. Testes: `ValidatesTenantOwnedSoftDeletesTest` + suite Requests 32 OK
7. ADR atualizado: `.harness/decisions/ADR-2026-11-23-form-requests-multitenant.md`
